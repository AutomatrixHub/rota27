# Rota 27 v0.15 — Sincronização multidispositivo

Status: **DEV.1 — não publicar na `main`**

## Objetivo

Permitir que dois ou mais aparelhos operem o Rota 27 compartilhando comandas, histórico e cardápio sem abandonar o princípio offline-first.

A v0.14 continua sendo a produção estável. A v0.15 é desenvolvida na branch `feature/v0.15-multidispositivo`.

## Arquitetura DEV.1

```text
Aparelho A                         Aparelho B
localStorage                      localStorage
     │                                 │
     ├─ outbox local                   ├─ outbox local
     │                                 │
     └──────────► Edge Function ◄──────┘
                  rota27-sync
                       │
                       ▼
              rota27_sync_events
              rota27_sync_devices
                  Supabase
```

O aplicativo continua gravando primeiro no armazenamento local. Quando há internet, as alterações entram em um log remoto idempotente. Cada aparelho mantém um cursor e busca somente eventos posteriores ao último sincronizado.

## Eventos sincronizados

- `state_snapshot` — fotografia completa usada na inicialização/compactação;
- `command_opened` — abertura de comanda;
- `command_patch` — mesa/local, cliente e dados autorizados do WhatsApp;
- `item_delta` — incremento/decremento de quantidade por produto;
- `command_closed` — fechamento de comanda;
- `history_upsert` — registro histórico importado/restaurado;
- `catalog_upsert` / `catalog_delete` — alterações de produtos;
- `categories_replace` — categorias e status.

A fila de envio do WhatsApp **não é sincronizada** entre aparelhos. Ela permanece local para evitar duplicidade de mensagens.

## Conflitos

A estratégia principal para itens é delta aditivo. Assim, lançamentos feitos quase ao mesmo tempo em aparelhos diferentes podem ser somados sem substituir a comanda inteira.

Se um evento de lançamento chegar para uma comanda que já está fechada naquele aparelho, o evento não é aplicado silenciosamente: ele é preservado como aviso de conflito na configuração da sincronização.

## Bootstrap seguro

A sincronização não substitui dados automaticamente no primeiro uso.

### Primeiro aparelho

1. configurar a Edge Function e o token;
2. clicar em **Publicar este aparelho como base**;
3. é criado um `state_snapshot` inicial.

### Demais aparelhos

1. configurar a mesma Edge Function/token;
2. clicar em **Adotar base compartilhada**;
3. o Rota 27 salva uma cópia local em `rota27_sync_pre_adopt_backup_v1`;
4. o aparelho baixa o snapshot mais recente e os eventos posteriores.

## Funcionamento offline

- as operações locais nunca dependem da disponibilidade do Supabase;
- mudanças são acumuladas em `rota27_sync_config_v1.outbox`;
- ao recuperar internet, o app tenta sincronizar automaticamente;
- também sincroniza ao voltar para o primeiro plano e a cada ~15 segundos enquanto estiver ativo;
- o envio é idempotente por `event_id`.

## Backend

### Migration

Arquivo:

`supabase/migrations/20260819_create_rota27_sync.sql`

Cria:

- `public.rota27_sync_events`;
- `public.rota27_sync_devices`.

RLS fica habilitado e **sem policies públicas**. O acesso ocorre somente pela Edge Function usando service role.

### Edge Function

Arquivo:

`supabase/functions/rota27-sync/index.ts`

Endpoint esperado no projeto atual:

`https://owkvwsiblbzlpxjwybrt.supabase.co/functions/v1/rota27-sync`

Autenticação:

`x-rota27-device-token`

A função usa o mesmo secret `ROTA27_DEVICE_TOKEN` já empregado na integração de WhatsApp. O secret opcional `ROTA27_SYNC_STORE_ID` pode ser criado; se ausente, o valor padrão é `rota27-bodega`.

**Deploy obrigatório com Verify JWT OFF**, pois a autenticação é própria.

## Limitações conhecidas do DEV.1

- ainda não há login individual por funcionário;
- a autorização é por token de dispositivo compartilhado;
- um lançamento feito offline depois que outro aparelho já fechou a comanda vira conflito e exige revisão operacional;
- não há compactação automática periódica do log no servidor além de snapshots manuais/por mudanças locais muito grandes;
- o backend ainda precisa ser aplicado/deployado antes do teste real entre dois aparelhos.
