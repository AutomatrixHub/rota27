## Deploy por PowerShell

O script faz uma verificação de branch, vincula o projeto, lista migrations e executa primeiro um `db push --dry-run`. Nenhuma migration é aplicada até o operador digitar exatamente `PUBLICAR`.

```powershell
cd "C:\Users\marco\OneDrive\Documentos\Rota27\mvp\Rota27-comandas-git"

powershell -ExecutionPolicy Bypass -File ".\scripts\deploy-v015-sync.ps1"
```

Fluxo esperado:

1. Supabase CLI é carregada via `npx`;
2. projeto remoto é vinculado;
3. histórico de migrations é exibido;
4. `db push --dry-run` mostra o que seria aplicado;
5. o operador revisa e digita `PUBLICAR`;
6. migrations pendentes são aplicadas;
7. `rota27-sync` é publicada com JWT da plataforma desativado;
8. o endpoint final é exibido.

Endpoint esperado:

`https://owkvwsiblbzlpxjwybrt.supabase.co/functions/v1/rota27-sync`

## Importante sobre migration history

Se o `db push --dry-run` mostrar migrations inesperadas ou divergência do histórico remoto, **não digite `PUBLICAR`**. Interrompa e revise o histórico antes de qualquer alteração no banco.

## Depois do deploy

No preview v0.15:

1. Cardápio → **Sincronização entre aparelhos** → Configurar;
2. usar **Usar URL/token já configurados no WhatsApp** ou preencher manualmente;
3. salvar;
4. no aparelho escolhido como principal, clicar **Publicar este aparelho como base**;
5. somente depois conectar um segundo aparelho e usar **Adotar base compartilhada**.

## Rollback da DEV.1

A v0.14 não depende das tabelas novas nem da função `rota27-sync`. Portanto, durante o desenvolvimento, basta manter a `main` sem merge para que os iPhones de produção continuem operando como antes. A sincronização também pode ser desativada individualmente em cada preview sem apagar os dados locais.
